# ADR-0009: BOSS 采集改人工浏览 + F8 只读页面提取

- **日期**：2026-08-13
- **状态**：已接受
- **关联**：issue #62；替代方案评估见 docs/research/boss-zhipin-crawlability.md（反爬行为时间线）

## 背景

#56 的 BOSS 自动采集（隐藏窗口加载搜索页 → 页面内补发 fetch joblist.json）被 BOSS 服务端风控命中：风控是会话/IP 累积维度的渐进升级（code:37 → code:200404 → 页面层刷新循环），多次采集后连坐同一 `persist:boss` 分区的可见浏览窗口。调研已点名「页面稳定后的补发 fetch」为高危动作。

## 决策

BOSS 岗位信息获取从**自动采集**改为**人工浏览 + 只读页面提取**：

- 用户在内置 BOSS 窗口正常浏览岗位详情页，按 F8；
- 主进程经 `webContents.executeJavaScript` **只读**收集页面文本（title / body innerText / h1 / URL）——零额外网络请求、零 DOM 修改、零页面注入、零自动化导航，不产生任何新风控信号；
- 识别/映射逻辑在主进程**纯函数**中完成（可单测，符合 spec Testing Decisions 解析与抓取分离原则）；
- 提取结果经 IPC 事件预填手动录入表单，用户核对后保存（沿用「预览确认」哲学，不自动入库）。

自动采集通道（BossFetcher）代码保留但不再作为推荐路径（牛客/猎聘自动采集不受影响）。

## 后果

**正面**：

- 消除 BOSS 风控的主要信号源（补发 fetch + 批量窗口导航）；可见窗口不再被采集连坐；
- 提取逻辑纯函数化，回归测试可锁定（spec Testing Decisions）；
- 登录态下提取的是页面渲染结果，薪资可见性问题（匿名会话 salaryDesc 为空）自然消失。

**负面**：

- 无批量能力：一次提取一个岗位，效率上限 = 人工浏览速度（产品定位为个人低频求职工具，可接受）；
- DOM 结构依赖：BOSS 页面改版需更新提取识别规则（纯函数部分有 fixture 单测兜底；页面结构靠手动冒烟验证）。

**风险**：无新增。用户人工浏览属于正常使用形态。
