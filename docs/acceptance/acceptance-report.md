## 本次实时验收尝试与 blockers

尝试（2026-08-19，本机）：
1. 启动应用 → 窗口初始离屏（−25600）→ 重启后窗口可见并置前 → **真实鼠标点击导航到 #/resumes** 成功；
2. 点击「上传解析」→ 应用失去焦点（原生文件对话框预期出现）→ 键入完整路径 + Enter 未能完成选择；
3. 诊断发现桌面存在多个**拦截真实点击的悬浮层**（NVIDIA Overlay、PiDeck 等；WindowFromPoint 显示点击点被 pid 3696 透明窗口覆盖）；
4. 本会话模型**不具备图像视觉**，无法按手册要求以截图核验每一步 UI 状态。

Blocker 结论（按 #83 与 #73 的 blocker 记录约定）：
- **B1 视觉核验缺失**：Computer Use 验收以截图核验为核心；本模型无法读取截图 → 无法完成可核验的端到端驱动。
- **B2 桌面悬浮层干扰**：真实点击被 overlay 拦截（偶发），文件对话框键入未落盘。
- **B3 OCR 语言包缺失**：扫描型 PDF 真实 OCR 无法跑通（错误路径可验收，成功路径待语言包）。
- **B4 独立 Pi 认证缺失**：Kimi 三路径对比无法运行（#80）。

以上 blocker 与 #79/#80 的记录一致，均非应用缺陷（应用自动化测试全绿，栅格化经真实 Electron 验证）。
