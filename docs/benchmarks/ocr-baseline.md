# Windows OCR 基准与逐页路由阈值（#79）

> 本基准回答两个问题：1) 逐页路由的硬/软异常初始阈值从哪来、如何校准；2) Windows OCR
> 在代表性环境上的质量与耗时证据。**这些阈值是待校准的初始值，不是行业标准**（#73 Further
> Notes：实施时应记录阈值来源，避免把当前初始分数误认为行业标准）。

## 初始阈值来源（#73 规格 → 实现）

逐页路由实现位于 `src/main/services/pdf-page-quality.ts`，常量集中定义并注释「初始值」。

| 信号 | 初始值 | 规格来源（#73） |
| --- | --- | --- |
| 控制/私用区字符占比（硬） | `HARD_CONTROL_RATIO = 0.05` | 「控制字符或私用区字符占比达到初始 5% 阈值」 |
| 无文本层但有视觉内容（硬） | text 为空 + `hasVisualContent` | 「页面有明显视觉内容但无文本层」 |
| 替换字符/NUL（硬） | 出现 `\uFFFD` / `\u0000` | 「出现替换字符或 NUL」 |
| 视觉内容与文本量严重不匹配（硬） | `HARD_VISUAL_TEXT_MIN = 30` 字符 | 「视觉内容与文本量严重不匹配」 |
| 有效中英文/数字比例 < 70% | +30 分 | 「有效中英文或数字比例低于 70%（30 分）」 |
| 文本稀少且页面内容丰富 | `SOFT_SPARSE_TEXT_MAX = 120` 字符 + 视觉内容，+30 分 | 「文本稀少且页面内容丰富（30 分）」 |
| 异常断词/碎片化 | 连续单字断裂 ≥ 1 组（`(?:[一-龥] ){3,}[一-龥]`），+20 分 | 「异常断词或碎片化（20 分）」 |
| 双栏或坐标阅读顺序异常 | 两侧 1/3 聚类 items 占比 ≥ `SOFT_TWO_COLUMN_RATIO = 0.6`，+25 分 | 「双栏或坐标阅读顺序异常（25 分）」 |
| 关键字段格式异常 | 截断日期 / 电话混字母 / 残缺邮箱，+15 分 | 「电话、邮箱、日期、GPA 等关键格式异常（15 分）」 |
| 重复、丢行或截断迹象 | 重复行或「多行末行极短无结束标点」，+15 分 | 「重复、丢行或截断迹象（15 分）」 |
| 软分 → OCR | ≥ `SOFT_OCR_THRESHOLD = 40` | 「初始总分达到 40 进入 OCR 或可靠的坐标重排路径」 |
| 软分 → 待确认 | `SOFT_PENDING_MIN = 15`–39 | 「15–39 保留文本但标记待确认」 |
| 软分 → 正常文本 | < 15 | 「低于 15 使用正常文本路径」 |

**实现时的两条校准决策**（记录来源，供后续基准修正）：

1. **碎片化用「连续单字断裂」而非单处空格**：简历行内字段分隔（如「北京理工大学 本科」）
   是正常排版，不是断词；只有连续单字断裂（如 OCR 乱码的「张 伟 北 京」）才计分。
   初始阈值 1 组（连续 3 字以上），待 OCR 基准校准。
2. **「内容很少但确实是正常尾页」不判截断**：截断信号要求「多行内容末行极短」，
   单行短页（如尾页一行「第 3 页」）不触发——防止所有稀疏页面被误 OCR（#73 页面检测
   测试要求覆盖此反例）。

## 运行方法

```bash
# 生成夹具（Windows + 微软雅黑；已提交则无需重跑）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/gen-ocr-fixtures.ps1

# OCR 冒烟/性能（全部夹具；或指定三页集）
node scripts/ocr-smoke.mjs
node scripts/ocr-smoke.mjs page1.png page2.png page3.png
```

前置条件：Windows + PowerShell + 中文(简体) OCR 语言包
（设置 → 时间和语言 → 语言 → 中文(简体) → 语言选项 → OCR）。

## 当前证据（初始基线）

实测于 2026-08-18（本机 win32/x64；见 `.checkpoint/ocr-smoke-report.md`）：

- 本地文本提取：PDF/DOCX 解析为纯本地 IO，随 #78 服务测试覆盖（无网络依赖）；
  代表样例 P95 远低于 1 秒目标（pdfjs/mammoth 单文件毫秒级）。
- Windows OCR：**Blocker —— 系统缺少 zh-Hans-CN OCR 语言包**，
  `win-ocr.ps1` 的 `TryCreateFromLanguage('zh-Hans-CN')` 返回 null → `ENGINE_FAIL`。
  每页约 1.4s 均为 PowerShell 启动 + 引擎检查，非实际识别耗时。
- 因此「OCR 每页 P95 ≤ 3s」「三页扫描简历 ≤ 10s」目标**当前无真实数据**；
  安装语言包后重跑 `node scripts/ocr-smoke.mjs` 记录真实数据并更新本文件。
- OCR 质量三路径对比（纯 Windows OCR / 多模态识图 / OCR 文本+多模态复核）属 #80，
  与本基准共享同一套合成夹具。

## 校准循环（后续 #82/#83 用）

1. 安装语言包后跑冒烟，记录每页耗时与关键字段命中（含 0/O、1/l/I 等易错字符）；
2. 将识别结果回灌 `analyzePageQuality` 的软/硬信号，比对「应走 OCR 的页是否被判 OCR」、
   「正常尾页是否误判」；按误判方向调整分值与阈值（分值/阈值均为命名常量，便于调参）；
3. 三路径对比数据 → 若多模态在准确率/耗时/成本/隐私上全面占优，经独立 ADR 改变默认路径
   （#73 OCR and multimodal boundary），不在本实现中隐藏切换。
